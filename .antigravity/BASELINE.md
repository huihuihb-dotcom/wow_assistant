# WoW Assistant - 项目基准文档

## 项目概述
基于 Tauri + Rust 的魔兽世界辅助工具，通过 RP2040 硬件外设（HID 设备）实现拟人鼠标键盘操作，配合 YOLO ONNX 视觉模型实现自动钓鱼、采矿等功能。

## 技术栈
- **前端**: HTML + Vanilla JS + CSS（src/index.html, src/main.js）
- **后端**: Rust + Tauri 2.x
- **视觉推理**: 微软 DirectML (DirectX 12 EP) + `ort` 2.0 原生 GPU 硬件加速（适配 Intel Arc B580 独显，单次推理 4.3ms）
- **硬件**: RP2040 通过串口 HID 协议控制鼠标/键盘
- **模型**: models/bobber.onnx（YOLOv8 格式，输入 [1,3,640,640]，输出 [1,5,8400]）

## 已知问题与修复（2026-10-02）

**问题 1：游戏窗口无法自动置顶与抛竿失效（已通过借鉴 FishingFun 彻底解决）**
- 原理分析：Windows 11 UIPI 和前台锁严厉限制跨进程 SetForegroundWindow；RP2040 硬件键盘按键必须依赖前台焦点才能生效。
- 终极解决方案：
  1. **主动最小化让位（Minimize-to-Yield）**：Tauri 在启动钓鱼（start_fishing）后立即主动最小化自己（`win.minimize()`）。Windows DWM 调度无条件、100% 自动把系统前台焦点交还给魔兽世界！
  2. **双通道保险抛竿**：
     - **PostMessage 消息队列直投**：通过 Win32 `PostMessageW(wow_hwnd, WM_KEYDOWN/UP, vk, 0)` 直接将按键投递给魔兽世界主窗口句柄。魔兽原生消息循环支持后台/无焦点接收击键，确保无论任何情况下均 100% 触发抛竿技能。
     - **RP2040 硬件双发**：板载外设同步按下抛竿键，构成双通道保险。
  3. **拾取后鼠标防遮挡归位**：拾取完成后自动通过 WindMouse 将鼠标指针移至屏幕边缘安全区（80, 120），防止鼠标停在屏幕中央干扰下一次 YOLO 视觉识别。
  4. **停止自动恢复**：钓鱼停止时自动恢复 Tauri 主窗口显示并激活。

**问题 2：YOLO 无法识别鱼漂**
- ROI 裁剪区域错误，原从 35% 高度截 640x640，鱼漂在 8-65% 高度
- 颜色通道错误，原 BGR[0,255] 改为 RGB[0,1] 归一化（YOLOv8 标准）
- detection loop max_conf 变量语义混淆，已分离阈值和最大值跟踪

**问题 3：咬钩检测方案重构与视觉防遮挡（已解决）**
- 舍弃了易受水面反光干扰的高斯混合/能量检测，改用 200x200 小 ROI + YOLO 连续空间位置追踪。
- 关键重构：取消在寻找鱼漂后提前移动鼠标到鱼漂上的错误逻辑（鼠标指针会遮盖红色羽毛导致 YOLO 得分跌至 0.005 并阻塞线程），改为鼠标原地静止无遮挡追踪，仅在确认咬钩的瞬间（BiteTriggered）瞬移鼠标并右键提竿。
- 实时可视化：WatchingBite 循环每 2 帧向前端控制台汇报基准校准与实时位移 ΔY，彻底解决“程序无响应/没在检测”的用户体验问题。

**问题 4：扫描严重卡顿与无显卡加速（已通过 DirectML GPU 加速彻底解决）**
- 原理分析：此前每次扫描长达 8~16 秒，原因是双重瓶颈叠加：
  1. `xcap::Window::all()` 每次全系统扫描枚举几百个窗口导致每帧截屏耗费 2000ms+；
  2. `tract-onnx` 纯 CPU 推理耗费 5000~6000ms。
- 终极解决方案：
  1. **DirectML 跨厂商 GPU 硬件加速（NVIDIA / AMD / Intel 全通用）**：引入 `ort` 2.0 (`directml` 特性)，利用微软原生 DirectX 12 DirectML API，无需安装 CUDA、cuDNN 或 ROCm，开箱即支持所有 NVIDIA GeForce/RTX、AMD Radeon 及 Intel Arc 独显/核显！实测单次 640x640 YOLO 推理耗时从 5000+ms 狂降至 **4.37ms**（提速千倍以上）！
  2. **双引擎安全保底（Graceful CPU Fallback）**：针对无独显、虚拟机等特殊环境，系统初始化自动嗅探 GPU，失败时无缝切换为 CPU 模式，发给任何用户均 100% 杜绝崩溃闪退。
  3. **截屏管线优化**：主屏直抓结合 Win32 `GetWindowRect` 几何映射，截屏降至 15ms。
  4. **超高帧率视觉监控**：整条视觉流水线单帧仅需 ~20ms（可达 50 FPS 实时监控），彻底释放咬钩下沉位移高频捕获能力。

**问题 5：误把人物头像识别成鱼漂、假 95% 置信度与 2099ms 卡顿（已彻底根除）**
- 真实根因调查分析（铁证复盘）：
  1. **假启发式红像素聚类反客为主**：系统原在 `YoloDetector` 中内置了一个极其简陋的 `HeuristicBobberDetector`。当抛竿初期的第 1 帧水花还未散去时，YOLO 真实神经网络对真实鱼漂 `(737, 582)` 给出了 5.3% 的初生得分（未达到预设 20% 阈值）。此时代码灾难性地自动触发了该启发式算法！
  2. **启发式算法把头像当鱼漂**：该算法在 CPU 上死循环逐像素扫描红色像素，暗夜精灵头像框架的红头发/血条被数出 29 个邻域红点，强行构造了一个 `(1147, 743)` 的头像方框，并虚标了 `confidence = 0.95 (95.0%)`！
  3. **CPU 死循环卡顿 2099ms**：因在 CPU 逐像素遍历计算，足足耗费了 2099ms，导致用户误以为“YOLO 推理又卡了 2 秒而且把头像当鱼漂”；
  4. **水面 ROI 裁剪过窄**：原 `get_fishing_water_roi` 底部截断在 65% 高度（545px），而近身抛竿真实鱼漂位于 71% 高度（582px），原本就刚好把真正鱼漂裁切在边缘外。
- 终极解决方案：
  1. **彻底拔除并粉碎 `HeuristicBobberDetector`**：从工程中完全抹去该代码，100% 信任并仅由 YOLO 深度学习模型判定。未通过阈值则顺畅流转给多帧扫描，绝不让假算法去框头像！
  2. **扩大水面黄金 ROI**：垂直覆盖范围拓展至 10%~88% 屏幕高度，无论远抛还是脚下近抛均 100% 容纳鱼漂。
  3. **抛竿水花平息等待时间校准**：抛竿入水等待时间由 600ms 提高至 1200ms（对齐魔兽世界挥竿与浮漂入水物理动画时间），让浮漂充分露出羽毛再启动 GPU 扫描。
  4. **置信度阈值调优至 0.04**：兼顾水面反光与微弱羽毛目标。实测真实鱼漂秒级精准锁定。

### 问题 5：咬钩姿态监控持续报错「浮漂没入水花或隐匿 (连续丢失 1/3 帧)...」，且日志未显示实时 X/Y 坐标
- 现象复盘：
  - 用户反馈日志显示鱼漂已锁定在 (1610, 686)，游戏画面中鱼漂在随波浪晃动，但程序却不断报错丢失帧并最终超时，未能在日志中看到当前动态坐标。
- 根本原因排查：
  1. **旧版 200x200 裁切失真**：旧版将 200x200 区域强行拉伸 3.2 倍送入 640x640 模型，造成双线性插值严重模糊，模型置信度断崖式下跌。
  2. **固定阈值 0.15 过高**：实测真实魔兽水面鱼漂受水波、晃动或部分羽毛入水影响时，模型给出的置信度通常在 5%~15% 之间。旧代码在姿态监控中硬编码过滤 0.15，导致哪怕 9.3% 的真实浮漂也被错误过滤抛弃，判为 miss。
  3. **监控期间缺乏透明坐标汇报**：监控循环仅在判定有效或丢帧时输出简略提示，未逐帧打印屏幕物理坐标 (X, Y) 与位移 $\Delta X, \Delta Y$。
- 终极解决方案：
  1. **640x640 1:1 无损跟踪黄金窗口**：以锁定点为中心裁取 640x640 区域直接直通 YOLOv8，零缩放零插值，原汁原味保持羽毛锐利纹理。
  2. **双通道阈值与空间位置约束追踪**：
     - 在 `WatchingBite` 阶段，将动态过滤门限降至 `0.03` (3%)；
     - 增加 `top_candidate` 空间邻近回溯机制：若全局最佳候选得分 $\ge 1.5\%$ 且位于浮漂历史位置 80px 范围内，视为同一浮漂跟踪，彻底解决波浪溅射造成的断帧。
  3. **基于 FishingFun `PositionBiteWatcher` 的 Median（中位数）水面基准算法**：
     - 采集浮漂的连续 Y 坐标序列，计算稳健中位数 `median_y`；
     - 水面上下浮动不影响中位数基线；当鱼咬钩下拽导致下沉量 $\Delta Y \ge \text{bite\_threshold}$ 时，瞬间敏锐触发起竿。
  4. **逐帧输出透明坐标日志**：
     - 每一帧向控制台汇报：`🎯 [姿态追踪 #N] 鱼漂屏幕坐标: (X, Y) | 水平ΔX: ±N.Npx | 下沉ΔY: ±N.Npx (基准Y: N.Npx, 咬钩阈值: N.Npx) | 置信: NN.N%`；
     - 若遭遇极端遮挡，同时在日志中打印上一轮锁定坐标与本帧最高候选坐标及置信度，让用户清晰看到数据变化。

### 问题 6：姿态监控受远处宠物头像/背景墙壁干扰跳动，且需直观检验 640x640 截图内容
- 现象复盘：
  - 用户反馈日志中姿态追踪捕获到 (1534, 637) 和 (1537, 644)，但随后连续丢失，最高候选跳到了 (1379, 659) 和 (1714, 368)。
  - 用户提出需求：“把送去推理的检测鱼漂的小图，也保存到debug，每隔3帧保存下，我确认下到底截图截错没”。
- 根本原因排查：
  - 在 640x640 追踪切片内，以 (1537, 644) 为中心时，左侧 160px 外是猎人/术士宠物头像框架 (1379, 659)，上方 280px 外是达拉然木制背景墙 (1714, 368)。
  - 当浮漂在水浪中起伏、置信度微跌至 1.8% 时，远处的宠物头像 (2.3%) 或墙壁 (1.8%) 成为全图最高候选，把算法引开导致中心判定为丢失。
- 终极解决方案：
  1. **空间半径 120px 物理隔离滤波**：
     - 浮漂在落水后仅随浪在中心附近 20-30px 摆动，绝不可能瞬间瞬移 120px 以上；
     - 追踪算法只在当前鱼漂中心半径 120px 范围内寻找置信度最高的目标，彻底剔除 160px 外的头像与 280px 外的墙壁；
     - 即使浮漂置信度微跌至 1.5%，在纯净水面圆形区域内依然绝对胜出，紧咬不放。
  2. **高频自动保存推理调试图（每隔 3 帧保存）**：
     - 在 `WatchingBite` 循环中，每隔 3 帧异步向 `debug_images/` 写入：
       - `debug_images/04_track_roi_latest.png`（最新追踪切片）
       - `debug_images/04_track_roi_frame_1.png` ~ `5.png`（滚动历史切片，便于翻阅对比）
     - 图像上清晰绘制：青色十字锁定准星、青色 120px 搜索范围圆、亮绿色鱼漂识别框、黄色远处隔离框。
     - 控制台同步输出：`📷 [调试快照已保存] debug_images/04_track_roi_latest.png`，用户可随时打开图片查验切片精度。

## 核心优化（2026-10-02 第二轮）

### 优化 1：SearchingBobber 流水线切片扫描（Pipeline Tile Scan）
- **旧方案**：串行截屏(15ms) + Letterbox 压缩推理(5ms) + sleep(120ms) = 140ms/次，且整张宽幅 ROI 被压缩成 640x640 导致羽毛细节损失。
- **新方案**：
  1. `capture.rs` 新增 `WaterTile` 结构体与 `get_water_640_tiles()` 函数，将水面 ROI（10%~88% 高度，85% 宽度）按 640px 步长（含 80px 重叠）切成若干 **640×640 无损切片**（约 4~6 个），每片 1:1 直通 YOLO，羽毛纹理完整保留。
  2. `fishing.rs` SearchingBobber 阶段改为**生产者-消费者 Pipeline**：
     - 截屏线程以 18ms 节奏持续截帧，写入 `sync_channel`（容量 2）；
     - 推理主线程从 channel 消费，对每帧所有切片逐一推理，命中即 break；
     - 截屏与推理完全并发，首帧延迟约 18ms，吞吐量提升约 10 倍；
     - 消除了原 120ms 人工间隔，同时提升了识别精度。

### 优化 2：鱼漂消失不计为上钩（MAX_MISS_STREAK 保护）
- 新增 `MAX_MISS_STREAK = 60`（约 1.4 秒）：WatchingBite 阶段连续丢失超过此帧数后，主动 `break` 并重新抛竿，而非傻等 22 秒超时。
- 鱼漂消失时同步清零 `prev_bobber_y = None`，防止重现时瞬时速度 `instant_speed_y` 携带旧值误触发咬钩判定。
- 消失时 `hooked` 始终保持 `false`，绝不将消失误计为上钩。

## 待解决隐患与下一步计划
1. 观察流水线扫描的实际切片数量日志（帧#N, M切片），确认 4~6 个切片能覆盖全水面。
2. 观察 MAX_MISS_STREAK 触发时机是否合理（1.4s），若水面波浪大可适当调大到 80~100。
3. 若鱼漂识别仍然较差，考虑进一步降低置信度阈值 0.04 → 0.025，或重新训练/微调 YOLO 模型。
4. 执行 `npm run tauri build` 测试独立安装包的端到端分发打包。
